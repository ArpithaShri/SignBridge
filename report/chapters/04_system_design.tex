\section{Overall System Architecture}
\label{sec:overall_architecture}
The SignBridge system is architected as a decoupled, multi-tier client-server application optimized for real-time video processing and deep learning inference. The high-level architecture comprises two primary tiers: (1) a client presentation tier built with React 19, TypeScript, and Vite, and (2) an asynchronous application and inference tier built with FastAPI, Uvicorn, OpenCV, and Keras 3 on Python 3.11. \section{Frontend and Backend Architecture}
\label{sec:fe_be_arch}
The frontend is modularized into feature components under \texttt{frontend/src/}:
\begin{itemize}
    \item \texttt{components/dashboard/}: Hero section, architecture benchmark cards, and vocabulary preview.
    \item \texttt{components/recognition/}: Video uploader, HTML5 webcam recorder, video preview player, and live recognition result cards.
    \item \texttt{components/comparison/}: Multi-model comparison suite with agreement matrix.
    \item \texttt{services/recognitionApi.ts}: Type-safe asynchronous HTTP client methods.
\end{itemize}

The backend organizes application logic across four core modules under \texttt{backend/app/}: \texttt{config.py} (registry and constants), \texttt{preprocessing.py} (OpenCV frame extraction and normalization), \texttt{inference.py} (\texttt{MultiModelInferenceEngine} singleton), and \texttt{main.py} (FastAPI routing and startup lifespan).

\section{Model Inference Workflow and Data Flow}
\label{sec:inference_workflow}
The end-to-end inference workflow translates an incoming video into top-1 and top-5 predictions through five sequential stages, depicted in Figure \ref{fig:pipeline_flow}.

\begin{figure}[htbp]
\centering
\input{figures/pipeline_flow.tex}
\caption{Five-stage inference pipeline flow in SignBridge.}
\label{fig:pipeline_flow}
\end{figure}

\begin{enumerate}
    \item \textbf{Ingestion}: Video bytes stream into a temporary disk path while enforcing a 100\,MB size limit.
    \item \textbf{Uniform Sampling}: Exactly 33 frames are extracted via linear index spacing: $\mathcal{I} = \lfloor \text{linspace}(0, T-1, 33) \rfloor$.
    \item \textbf{Spatial Preprocessing}: Frames are converted to RGB, resized using \texttt{cv2.INTER\_AREA} ($224^2$ or $112^2$), and normalized.
    \item \textbf{Neural Inference}: Tensors pass through the requested model in the pre-loaded engine singleton.
    \item \textbf{Consensus & Aggregation}: Frame probabilities are averaged (or sequence output extracted), mapped to ISL labels, and returned via structured JSON.
\end{enumerate}

\section{API Communication and System Workflow}
\label{sec:api_comm}
Communication occurs over HTTP/1.1 via four REST endpoints: \texttt{GET /api/v1/health} (system readiness), \texttt{GET /api/v1/model-info} (tensor shapes and preprocessing parameters), \texttt{POST /api/v1/recognize} (single-model inference), and \texttt{POST /api/v1/compare} (parallel multi-model inference). The user initiates analysis by uploading a file or recording via webcam; the client performs client-side validation, dispatches the request, and displays the top predicted word, candidate probabilities, and consensus agreement.
