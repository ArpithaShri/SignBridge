\chapter{Challenges and Limitations}
\label{ch:challenges}

\section{Observed Implementation Challenges}
\label{sec:observed_challenges}
During system development, three primary engineering challenges were resolved:
\begin{enumerate}
    \item \textbf{Container and Encoding Inconsistencies}: WebM and QuickTime streams from varied browser devices frequently lack frame-count metadata in container headers. A dual-path fallback was implemented in \texttt{decode\_video\_frames()} to sequentially buffer frames before linspace subsampling.
    \item \textbf{Preprocessing Protocol Parity}: Discrepancies in color-space (BGR vs. RGB), interpolation (\texttt{INTER\_AREA}), or normalization ($[0, 255]$ with internal rescaling vs. $[0, 1]$ float scaling) directly degrade inference. Preprocessing paths were strictly validated per model.
    \item \textbf{Temporary File Leakage}: Video buffers streamed to disk were wrapped in guaranteed \texttt{try...finally} blocks executing \texttt{os.remove(temp\_path)} to prevent server disk spooling leaks.
\end{enumerate}

\section{Current System Limitations}
\label{sec:system_limitations}
The current SignBridge implementation operates under the following technical boundaries:
\begin{enumerate}
    \item \textbf{Isolated Sign Constraint}: The system recognizes isolated lexical words; it does not transcribe continuous sentences or model co-articulation across multi-sign discourse.
    \item \textbf{Fixed 76-Class Vocabulary}: The recognition domain is bounded to the 76 classes in \texttt{class\_mapping.json}; out-of-vocabulary gestures are projected onto the nearest class distribution.
    \item \textbf{Spatial Resolution Tradeoff}: Standardizing frames to $224\times224$ pixels reduces computational overhead but limits resolution for fine distal finger flexions.
    \item \textbf{Monocular 2D Depth Ambiguity}: Standard monocular RGB video lacks depth coordinates, inducing ambiguity between forward-backward hand motion trajectories and scale changes.
\end{enumerate}
