\section{Frontend and Backend Implementation}
\label{sec:impl_overview}
The SignBridge frontend is built with React 19, TypeScript, and Vite. It utilizes a glassmorphism design system defined via CSS custom properties in \texttt{frontend/src/index.css}, featuring semantic color tokens (indigo brand, emerald health status, and amber warnings) and backdrop Gaussian blurs. The application periodically polls \texttt{GET /api/v1/health} every 6 seconds to track model readiness.

The backend is an asynchronous microservice in \texttt{backend/app/main.py} running under FastAPI and Uvicorn on Python 3.11 with TensorFlow and Keras \cite{abadi2016tensorflow}. Model weights and the 76-class mapping are loaded once during startup using FastAPI's asynchronous \texttt{lifespan} context manager:
\begin{lstlisting}[language=Python]
@asynccontextmanager
async def lifespan(app: FastAPI):
    engine.load_all() # Pre-loads MobileNetV2, Custom CNN, and CNN-LSTM into memory
    yield
\end{lstlisting}
This in-memory caching eliminates cold-start deserialization delays, ensuring sub-200\,ms inference response times.

The application provides dual video ingestion pathways:
\begin{itemize}
    \item \textbf{Video File Upload} (\texttt{VideoUploader.tsx}): Drag-and-drop or file browsing supporting \texttt{.mov}, \texttt{.mp4}, \texttt{.avi}, and \texttt{.webm} files up to 100\,MB with instant client-side validation.
    \item \textbf{Webcam Video Capture} (\texttt{WebcamRecorder.tsx}): Live video capture via HTML5 \texttt{navigator.mediaDevices.getUserMedia} and \texttt{MediaRecorder}, enforcing a 10-second timer and generating a \texttt{video/webm} blob for direct neural inference.
\end{itemize}

Users choose between single-model recognition (\texttt{POST /api/v1/recognize}) and tri-model comparison (\texttt{POST /api/v1/compare}). The comparison engine evaluates all three models in parallel, computing an agreement metric: unanimous (3/3 agree), majority (2/3 agree), or divergent.

\section{Error Handling and Resource Cleanup}
\label{sec:error_cleanup}
The backend streams uploaded bytes to temporary files and wraps inference in guaranteed \texttt{try...finally} blocks executing \texttt{os.remove(temp\_path)}, preventing disk leakage. Input validation returns standard HTTP status codes: \texttt{400 Bad Request} for invalid extensions or empty files, \texttt{413 Payload Too Large} for files $>100$\,MB, and \texttt{503 Service Unavailable} if model weights are missing.
