\section{Existing Challenges and Proposed Solution}
\label{sec:challenges_solution}
Dynamic sign language recognition presents distinct engineering and visual challenges: (1) temporal redundancy and high processing latency across multi-frame video, (2) inconsistent video durations and frame rates across consumer cameras, (3) visual ambiguity caused by rapid hand motions and self-occlusions, and (4) cold-start latency in web services that reload model weights per request.

The \textbf{SignBridge} framework resolves these challenges through:
\begin{itemize}
    \item \textbf{Uniform Temporal Linspace Sampling}: Exactly 33 frames sampled via \texttt{np.linspace(0, T-1, 33)}, neutralizing duration and frame-rate variations.
    \item \textbf{Standardized Preprocessing Pipeline}: Automatic BGR to RGB conversion, spatial resizing ($224\times224$ or $112\times112$), and model-specific numerical normalization.
    \item \textbf{In-Memory Singleton Inference Engine}: Persistent model caching in FastAPI avoiding cold-start reloads.
    \item \textbf{Tri-Model Benchmarking & Consensus Suite}: Comparative multi-model evaluation providing consensus analysis across MobileNetV2, Custom CNN, and CNN-LSTM.
    \item \textbf{Reactive Web Interface}: Modern React 19 / TypeScript single-page application with webcam recording and drag-and-drop video upload.
\end{itemize}

\section{Functional and Non-Functional Requirements}
\label{sec:reqs}
\begin{itemize}
    \item \textbf{Functional Requirements}: FR-1 Ingestion of \texttt{.MOV}, \texttt{.mp4}, \texttt{.avi}, and \texttt{.webm} files up to 100\,MB; FR-2 Live webcam capture up to 10 seconds via HTML5 MediaRecorder; FR-3 Uniform 33-frame extraction; FR-4 Model-specific tensor formatting; FR-5 Single-model inference with top-1 word, top-5 candidates, and measured latency; FR-6 Multi-model comparison endpoint with agreement count; FR-7 System health and model introspection endpoints; FR-8 Input validation and user error diagnostics.
    \item \textbf{Non-Functional Requirements}: NFR-1 Low latency ($<200$\,ms CPU inference for MobileNetV2); NFR-2 In-memory model caching; NFR-3 Guaranteed temporary file disk cleanup; NFR-4 Non-blocking UI responsiveness; NFR-5 Modular architecture; NFR-6 Secure Cross-Origin Resource Sharing (CORS).
\end{itemize}

\section{Assumptions and Constraints}
\label{sec:assumptions}
Key operational constraints include: (1) signers are positioned 0.5--1.5\,m from the camera with hands and upper torso visible under ambient lighting; (2) video clips capture isolated lexical sign words; (3) inference strictly enforces the 33-frame sampling protocol; and (4) the API is stateless with zero persistent storage of uploaded video clips.
